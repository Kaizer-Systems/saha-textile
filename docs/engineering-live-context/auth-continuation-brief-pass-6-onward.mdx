## 3. What this session delivered

computed style rather than by eye — all fourteen text properties identical. The PIN is entered

impossible on every platform rather than merely discouraged. A follow-up fixed three
owner-reported defects: a Clear key, cells that no longer change height when the first digit
lands, and borderless keys. No keypad key is `disabled`, because this theme paints
`.btn:disabled` as a solid filled block.

## 4. Corrections and wrong interpretations, so they are not repeated

Every one of these was a claim that turned out to be wrong. They are recorded because the
mistake is more instructive than the fix.

1. `developer-portal-storybook` typecheck was reported as failing across seven passes. It is
   NOT broken and the alias never needed changing: a type-shim with an explicit tsconfig
   mapping, committed in `9e950c83` before the session, resolves it. The 4e attempt to remap
   the alias was wrong. `pnpm typecheck` is 15/15 with 0 cached.
2. A privilege-escalation vulnerability was reported to myself during 6a — registration
   appearing to honour an injected `role: admin`. It does not. The handler hard-codes
   `role: 'customer'`; the assertion had filtered on `emailNormalized`, which registration does
   not reliably set, and matched a different account. No vulnerability existed.
3. The Log out control looked like a dead element with no attributes and no effect from a
   direct click. The template shows it opens a confirmation modal. Checking the source beat
   reporting the symptom.
4. A bodyless DELETE returning 400 instead of 409 was my own call setting a JSON content-type.
5. 5c.2 was scoped as "assignments with `user.permissions` as fallback". Written that way it
   is not behaviour-preserving, because the first assignment would silently revoke embedded
   grants. It ships as a UNION.
6. The 6a bootstrap check first sat at the end of the e2e and failed on its own success
   criterion, because every earlier check seeds an administrator. Ordering was part of the test.
7. A Prettier MDX parser collision destroyed a progress entry: an inline code span containing a
   double asterisk collides with bold emphasis, stripping spacing and list indentation. Never
   write a route glob that way in these documents.

## 5. Owed, deferred and unverified

This is the section to act on. Nothing here is blocked by anything except a decision or time.

### Built but not usable from a browser

- The admin Security Settings SCREEN does not exist. 6b delivered only the API. The PIN half
  of the admin browser E2E is therefore still owed, and the idle soft lock in 6c will want the
  same screen.
- No admin screen consumes `/admin/roles`, `/admin/permissions` or `/admin/users`. The
  permission registry is published for a grant UI that has not been built.

### Security gaps found while working, not yet closed

- WEAK-PIN POLICY IS NOT IMPLEMENTED. `AdminPin` validates only the six-digit shape, and the
  contract comment states that denylist and sequential/repeated rejection belongs in
  core-domain. No such module exists, so `000000` and `123456` are currently acceptable PINs.
  This is the most security-relevant item in this list.
- `setPinHash` clears `failedPinAttempts` and `pinLockedUntil` but NOT
  `pinRevalidationRequiredAt`. Removing a PIN while suspended therefore leaves a stale
  suspension flag on an account with no PIN. Decide whether that is correct before changing it;
  the locked decision says the suspension clears only when the new password is used.
- Deny-by-default covers only the NEW admin surfaces. Pre-existing privileged routes still use
  role checks — `PATCH /orders/:id/status` is `@RequireRoles('admin','staff')` with no
  permission. Converting them is a behaviour change that needs its own pass and its own
  lockout analysis.
- A bodyless DELETE carrying `content-type: application/json` answers 400 rather than the
  intended status. Angular does not set that header on a bodyless request, so no client is
  affected today, but other HTTP clients do.

### Contract and model debt

- Neither Angular app depends on `@saha-textile/contracts`. The gateways still hand-write their
  wire DTOs. The pass-3 brief now marks 3d DONE with evidence describing the http-transport
  contract-alignment test, which is a different thing from the row's own title. Resolve that
  discrepancy explicitly rather than inheriting it.
- The embedded `user.permissions` array is transitional. Effective permissions are the UNION of
  it and role assignments; retiring it is unscheduled work, and until then
  `AdminInvite.permissions` and `UserAuthState.permissions` stay permissive `string[]` on read.
- Last-administrator protection counts ASSIGNMENTS only, so an account holding administrative
  power through embedded permissions is not counted. It deliberately over-refuses.
- `AuditLogListQuery` is documented in contracts as `GET /admin/audit-logs`. No such route
  exists, so nothing can read the audit trail these passes have been writing.
- The build prompt requires an admin session list and per-session revoke. Only a session COUNT
  exists, added in 6b.
- Registration-created user documents did not reliably expose `emailNormalized` in a lean read,
  which is what produced correction 2 above. Worth a short investigation into which write paths
  set it, because lookups elsewhere filter on it.

## 6. Harness lessons worth keeping

The e2e suite grew from 10 checks to 24 and leaked three times. Each leak made its own
"0 remaining" claim untrue.

- Per-check cleanup is skipped when an assertion throws, so aborted runs poisoned later ones.
  RBAC rows are now cleared unconditionally in teardown.
- Audit rows and email-verification tokens accumulated silently. The teardown now enumerates
  every collection and FAILS the run naming any that is still populated.
- Refusal assertions create accounts nobody tracks when a refusal fails, so users are cleared
  wholesale rather than by tracked id.
- A negative-control runner reported MISSED for runs that never executed, because the Mongo
  container had stopped. Any mutation runner must refuse to interpret a run that produced no
  tally, and must restore the source in a `finally`.
- `JWT_ACCESS_TTL` is one second in the e2e so the expiry case is genuine, which means admin
  sessions age out mid-check. RBAC checks rotate once and replay, mirroring the interceptors.

Two mutations were ABSORBED rather than caught, and both were correct outcomes demonstrating
defence in depth: swapping the guard's active-assignment query changed nothing because the
resolver filters revoked assignments itself, and removing either bootstrap refusal alone still
left the bootstrap refusing.
