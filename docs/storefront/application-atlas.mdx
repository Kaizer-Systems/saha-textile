## How to read the cards

- **Implemented** describes working behaviour within the stated limits.
- **Scaffolded** means the route, component or state exists while integrations are incomplete.
- **Planned** is approved direction, not available behaviour.
- Expand **Source files** to see the code behind each statement.

## Common misunderstandings

### "The cart is implemented"

The browser cart works: actions, effects, selectors, optimistic updates and persistence exist. It does not use the server cart API. Ownership, pricing, stock reservation and checkout are separate concerns.

### "Server rendering makes everything server-safe"

Dynamic rendering is enabled, but browser-dependent components still need `isPlatformBrowser()` or an equivalent guard. Public data is fetched on the server, with a 2.5-second timeout per API call. Past that limit the page renders without the data and the browser fetches it after hydration.

### "Language switching means Bengali is ready"

Transloco runs with English and French. Locale membership is configuration, not a fixed contract, so Bengali can be added once its content and validation are ready. Every page sits under a locale prefix, and the switcher is a set of links to the same page in the other language.

### "A social callback means signup is complete"

An unknown provider identity creates a server-held pending signup and opens registration. The page restores the record after a reload, locks a provider-verified email, hides password and provider choices that do not apply, and collects the remaining phone proof. Leaving through in-app navigation discards the record. A provider-proven email that already has an account is offered a one-time code instead.
