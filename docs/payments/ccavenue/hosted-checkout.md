# CCAvenue hosted checkout

Source: HDFC VAS CCAvenue integration guide, section 2, Payment Integration. Classification on that guide: Public.

The guide says the HDFC payment integration kit collects payments with credit cards, debit cards, Wallet, net-banking, UPI, BQR, and the other modes it names. Section 2.1 is titled Transaction Flow. The pages that follow are the request parameters, response parameters, configuration, sample, kits, and error codes.

The guide says to encrypt the request string using the AES-128 algorithm using the key provided by the bank. It does not state cipher mode, IV, padding, or key derivation.

## 2.2 Request parameters

The merchant creates a string from these parameters. HDFC will not check uniqueness of `order_id`. It generates its own payment reference number for each order the merchant sends.

## 2.4 API configuration details

Printed placeholders:

```text
merchant_id <provided by bank for UAT integration >
access_code <provided by bank for UAT integration>
enc_key <provided by bank for UAT integration>
```

The guide says the merchant developer updates these sample pages provided by the bank:

- `dataFrom.htm` — MID, redirect_url, cancel_url
- `CcavResponseHandler` — acces code and working key
- `CcavRequestHandler` — working key

Those sample pages were not in the PDF attachments.

## 2.6 List of integration kits

## 2.7 List of error codes

| Error code | Error description as printed                                                                                                                                                          |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 10001      | Invalid encryption request. Check the access code and the working key parameters passed in the ccavrequesthandler and ccavresponsehandler files and ensure there are no spaces.       |
| 10002      | Incorrect merchant_id, incorrect access_code, or request posted on an incorrect HDFC Bank post action URL. The gateway does not report which of the three is wrong.                   |
| 10003      | No payment options are allocated for completing the transaction.                                                                                                                      |
| 10004      | UPI amount greater than the threshold limit, printed as currently Rs.100000, set by NPCI.                                                                                             |
| 21001      | `order_id` parameter is blank.                                                                                                                                                        |
| 21002      | `currency` parameter is blank.                                                                                                                                                        |
| 21003      | `amount` parameter is blank.                                                                                                                                                          |
| 41004      | Customer clicked Back/Refresh on the browser. The guide says to ask the customer to initiate a fresh transaction and not to click back/refresh while the transaction is taking place. |
